# Overview and vacancy localization; draft preservation

Prepared after PR #26. OverviewPanel and VacancyPanel use typed RU/EN copy/default RU and receive controlled workspace data/callbacks from WorkspacePage. Production wrappers still fix RU; no English route, locale cookie/query or public switch is enabled. Confirmed facts and tracker counts use the same existing calculations; the overview explicitly says confirmations and manually recorded applications do not verify hh.ru submissions/responses.

Demo is disabled for an existing saved original **or saved facts**, including legacy empty-original records. It is also disabled when either the resume or vacancy draft differs from its saved value. This prevents a demo from overwriting unsaved source text. A synchronous pending ref prevents a second callback before rendering. The canonical request still contains only action/revision/expectedOwnerId; server demo constants, history, versions and write authorization are unchanged.

There is also protection for edits made **after** a source-replacing request starts. For import/demo/fact responses, WorkspacePage uses functional updates: replace a field with the returned saved source only if its current value still equals the value captured when the request began. Later resume/vacancy edits remain drafts. The returned workspace/revision still updates, so future explicit writes use the known current revision. A completed demo navigates to profile only if the user is still on overview; a later navigation choice wins. These are client draft/navigation guards, not a new backend authorization or cancellation guarantee. Existing owner/revision/unknown-write-result recovery remains intact.

Vacancy text stays controlled in the parent; link/result state is local to its card. Syntactic ID validation reuses the existing vacancyId function synchronously and performs no network lookup. Editing or clearing a link clears its old result; URL feedback cannot clear an unrelated service error. A valid syntax result explicitly says API access is not connected and asks the user to paste text. IDs, text, source labels, Unicode and canonical request bodies are not translated or normalized by locale.

The existing fictional vacancy examples remain unchanged Russian data, labeled as Russian examples; their buttons use lang=ru. Selection changes only the draft. Save and analyze remain explicit actions, with analysis enabled only for a nonempty saved vacancy matching the draft and a saved original profile. The30,000-character textarea limit is unchanged. No hh.ru request or write is added.

Seven new actual WorkspacePage fixture cases cover both source-draft demo blocks, legacy saved-fact protection, one canonical demo command/source/history, late demo/source edits/navigation, local ID/example behavior with zero hh.ru calls/autosaves, and explicit vacancy save/manual retry/analyze preconditions while preserving the next draft. English390 overview/vacancy axe/no-overflow checks and screenshots complement existing production Russian a11y/keyboard/offline/owner/recovery regression. The initial version fixture omitted its required vacancy field and was rejected by workspace validation; it was corrected before the successful full run. These responses are synthetic/intercepted; they are not live provider or hh.ru acceptance.

Source/frozen templates must not be translated in place. Real SMTP/recovery, Supabase provider restore/RPO/RTO, operator privacy/hosting/retention, live own model/HH/PWA/security/final acceptance remain open.
