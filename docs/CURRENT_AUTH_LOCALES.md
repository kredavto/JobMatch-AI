## Identity, consent and pending work

The existing Root owns credentials, registration mode and request/owner adoption. AuthPanel adds a synchronous pending guard, numeric/code-based feedback and presentation. Initial load/upload logic is byte-identical to #92. The action pipeline matches #92 after removing explicitly added local feedback/consent state calls; request bodies, methods, owner/revision guards, backend auth parsing and permission behavior are unchanged. Auth email input is now bounded200 to match the existing server schema.

Storage consent no longer carries into a new registration context. Email edits or explicit auth-mode changes clear the local checkbox. Recognized confirmation acknowledgement, successful workspace adoption and successful logout/delete clear it too. Language changes preserve the current choice and do not submit a request. This is client context hygiene, not a new privacy policy or storage authorization. The **existing placement/processor disclosure is retained verbatim in RU and translated in EN**; its country/processor claim is not verified or approved by this extraction. The operator must verify/correct actual placement, policy, retention and deletion before publication. This stage does not close the user's PD decision or approve new purposes/recipients.

Pending auth/mail form fields and auth-mode changes are locked; submitted values remain the request's context. Language changes preserve fields/caret, consent, phase, pending identity, cooldown and code; no effect is keyed by locale. Editing an idle address clears prior receipt/error feedback without clearing a pending guard or the confirmation cooldown. Feedback retains status/stage or closed keys and re-renders in the current language after held replies. Auth feedback uses #91's closed code/status catalog and its explicit bounded legacy same-origin RU compatibility; unknown/coded raw diagnostics do not become UI copy.

Confirmation and recovery notices acknowledge request handling conditionally, without promising delivery/account existence. Neither an opaque200 nor translated copy proves SMTP delivery. Confirmation cooldown stays60s across language/address edits and permits only a later explicit retry. Active-instance cleanup prevents a post-unmount response from creating a detached cooldown timer. Recovery code is removed from the URL at mount, exchanged only after explicit action and retained through locale changes until exchange; no automatic exchange/update/retry is added. Synchronous guard prevents duplicate same-frame password requests. Mismatch errors translate; request completion clears password/repeat as before. Partial/unknown session-revocation feedback remains explicit, and an unknown password update says to try sign-in first rather than immediately resend.
