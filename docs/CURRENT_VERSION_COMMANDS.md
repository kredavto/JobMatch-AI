## Trust boundary

SQL validates allowed owned confirmed facts, literal rendering and the shape/fixed constants of rules metadata. It does not independently recompute relevance or authenticate aggregate score supplied directly to the public RPC. An authenticated owner can submit a shape-valid self-reported aggregate there. The official HTTP path recalculates it from saved revision; score is never used for authorization. The result is deterministic rules-v1, not a qualified AI model, semantic proof or ATS guarantee. There is no new external LLM request or generated paraphrase. Future rules changes need matching SQL/contract updates and current parity tests.

Current source-backed profile fields remain unchanged/current after version/restore while their DTO workspace revision advances. Accepted letter history stays immutable, and an unaccepted old preview still fails workspace CAS. No verification or source-field approval is inferred from creating/restoring a resume version. Existing HMAC letter receipts are separate from these rules aggregates; do not describe score as signed or SQL-attested relevance.
