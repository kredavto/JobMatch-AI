# Free-text profile preview — source grammar v2 candidate

This is an optional **unsaved own-model preview**, not accepted profile extraction, a verified model, an immutable accepted-AI version or semantic fact checking. The existing manual structured-profile editor and separate confirmation remain available. No model suggestion is adopted into a record, fact, score or resume automatically. Durable accepted-change provenance is still a separate unfinished block.

## Source contract

`paragraph-quotes-v2` uses the saved structured-profile source, not browser-supplied text. Limits:12000 Unicode code points/48000 UTF-8 source bytes,40 paragraphs including excluded ones,2000 points per paragraph,10 suggestions,500 points/1000 UTF-16 units per non-null quote,64000 request/response bytes,60000 model-content units. Overflow fails without truncation or fallback. These byte/character limits do not guarantee that every document fits a particular deployment's tokenizer/context; real documents/capacity still require acceptance.

A paragraph is a group of nonblank lines, with blank lines separating groups. CRLF,CR,LF,U+2028 andU+2029 line separators are preserved in source ranges. Whitespace-only lines separate groups; original paragraph text/indentation and Unicode normalization are not rewritten. Malformed UTF-16, forbidden controls, absent input or no eligible paragraphs fail before inference.

The existing conservative `evidenceIssue` rule excludes an **entire** paragraph containing a recognised negation, intention or instruction. IDs retain their physical paragraph positions, including holes for excluded paragraphs. Only eligible `{id,text}` paragraphs are sent to the model: no excluded text, workspace/owner/fact IDs or vacancy. This rule is neither comprehensive injection defence nor semantic interpretation; it can miss risk or exclude useful text. Manual selection remains necessary.

Candidate v2 (`profile-paragraph-quotes-v2`) keeps the prompt text and server domain rules unchanged but emits four kind-specific JSON schema branches: required non-null title for employment/education/certification, required description for achievement, credential null outside certification. Each branch restricts blockId to the physical eligible IDs of this exact source (including holes). Unknown mandatory content still means omit the entry, never generate a fallback. Source text is not embedded in grammar enums. Schemas are rebuilt per request without shared mutable cache. Old v1 previews fail closed; historical v1 evaluation below is not v2 model evidence. JSON grammar support for anyOf/const is present in the [pinned official llama.cpp converter](https://github.com/ggml-org/llama.cpp/blob/8642541b255bfb5dc39cd351a178be09013a55d6/common/json-schema-to-grammar.cpp#L916); actual inference results remain separate.

The strict model response has entries with `blockId`, one of four kinds and all six field keys (`title,organization,start,end,description,credential`), each an exact literal quote or null. Employment/education/certification require a literal title; achievement requires description; only certification may have credential. Unknown required content should result in omitting a record, not inventing a value. Empty entries remains empty, not a generated fallback.

The server resolves every quote itself using code-point matching within the selected eligible whole paragraph. Missing, repeated or overlapping ambiguous occurrences are refused rather than choosing an offset. Model-supplied offsets, added properties, normalization, translation, invented values, duplicate records and absent required fields are refused. All fields in one record belong to one selected paragraph. A source range proves membership, **not** whether the kind, dates, organization, qualification or statement is true or correctly interpreted.

Dates remain verbatim; `dateInterpretation=not-performed` always. Missing fields are explicit unknowns. Existing conservative literal Gregorian/precision/order warnings annotate uncertain or reversed dates without rewriting them, calculating experience or establishing their meaning.

## Authorization and transport

`JOBMATCH_AI_PROFILE_ENABLED=false` is the default and is independent of the existing AI-review switch. Enabling requires the existing explicit own-model configuration plus `JOBMATCH_AI_PROFILE_MODEL_REVISION=sha256:<64 lowercase hex>`. This revision remains **operator-declared**; it does not attest remotely loaded weights. The normal production HTTPS/token/configuration restrictions apply. Operator hosting/data-processing/logging/retention/cost decisions and independent model acceptance must precede production activation; this PR enables none of them.

POST `/api/ai-profile` checks same origin, authentication, owner hints, a strict1024-byte consent/revision body, configuration and the existing shared authenticated analysis quota. It reads the private profile, checks workspace/profile revisions and source-match, calls the model, and performs another authenticated read. Changed owner/revision/source/source-workspace revision/fact-ID list or source mismatch rejects the late preview. Session revocation on that read cannot disclose the result. Quota consumption is not a profile/fact write. No SQL migration/table/backup format changes are needed here.

The provider sends the selected prompt/JSON schema/eligible paragraphs only, temperature0/maxTokens2048, no streaming, redirects or retries. It uses the existing20s owned request bound/15s bounded-body read and requires an explicit completed `stop` envelope. Errors are fixed catalog codes, never raw provider bodies, diagnostics, URLs, tokens or abort reasons. Optional static error-only diagnostics distinguish raw/domain shape (`review-schema`), selected-block/unique-source membership (`citation`) and duplicate-record validation (`review-validation`). These stages do not establish semantic correctness. Observer failure does not change validation or accepted result bytes.

## Browser lifetime and export

Typed RU/EN controls require fresh consent per request and synchronously prevent duplicate calls. Cancellation aborts owned work and ignores late replies; it does not undo text already delivered to the operator endpoint. Owner/source/revision/disabled changes, explicit profile refresh and unmount discard consent/results and cancel pending work. Locale-only changes preserve them without replay. Manual draft fields are never overwritten. Browser response validation binds both revisions/owner and reconstructs literal ranges, full context, unknowns and warnings again before display/export. Forged `accepted`/identity flags are rejected.

Preview/close/download do not call the structured-profile write command or confirm a fact. Explicit JSON download contains the full locally held source (including excluded paragraphs), fact-ID association, revisions, literal contexts and operator-declared model/prompt/contract provenance. Download is local, not model egress. It is an editable review snapshot, **not immutable database provenance for accepted AI changes**. There is deliberately no AI adopt/save action yet. No localStorage/server persistence of preview or consent is introduced. Owned blob URLs are revoked; fields/context/digests wrap on mobile.
