# Workspace feedback localization

Prepared after PR #24. Production `/` renders `WorkspacePage` with its default `ru` locale. No query, cookie, route or visible language switch enables a partial English interface. The extracted component accepts an optional locale for test-only composition and eventual completed locale wiring.

`lib/i18n/workspace-feedback.ts` holds typed RU/EN notice keys and interpolation arguments for reload, reauthentication, opaque registration, export, save, OCR/extraction, validated vacancy IDs and clipboard feedback. Error state retains a RequestError or a closed fallback key. Rendering resolves the current locale rather than storing a translated sentence. HTTP status remains authoritative for authentication, conflicts and unknown write results; locale changes never trigger a read, retry, mutation, field reset or remount.

Internal client validation now has explicit CLIENT_OWNER_CHANGED, CLIENT_HISTORY_INVALID, CLIENT_ANALYSIS_INVALID, CLIENT_EXPORT_INVALID and CLIENT_IMPORT_INVALID codes. These are **client-only** codes: `errorFromResponse` still accepts only known public API codes with matching HTTP status. External JSON cannot claim a client code or bypass validation. Previously loaded history, failed exports, invalid extraction and owner recovery retain their specific context in either language.

Unexpected JavaScript/JSON exceptions use a fixed domain fallback, never arbitrary exception.message. In particular, an invalid non-JSON import response cannot reflect a fragment of the response in UI text. The existing review draft remains unchanged and no master-profile write is implied. Starting another import clears its earlier success notice; an extraction error cannot coexist with a stale “text extracted” message from that notice.

`app/page.tsx` is a small server wrapper around the extracted client workspace component. No server-side profile fetch, persistence or locale transport is introduced. Existing typed navigation/labels and prepared profile/structure/task components receive the same locale in the test composition. Source text, IDs, revisions, canonical commands, filenames, persisted status values and frozen document templates are unchanged. Password/session/owner/revision guards remain in the same handlers.

Five new actual-component browser scenarios bundle WorkspacePage into an ephemeral loopback fixture (pinned existing dev esbuild). Synthetic API replies test an in-flight write conflict, OCR notice/invalid success reply, initial outage/manual retry, malformed JSON redaction and opaque registration feedback while changing the locale. They assert unchanged owner/revision/action/text, drafts/DOM selection, one request per explicit action and no import autosave. A mobile feedback screenshot and overflow check supplement the full Russian app regression, including existing axe/keyboard/offline/recovery checks. These are not live Auth/SMTP/OCR/provider/model checks; the file responses and registration are intercepted.
