One client context supplies default Russian or explicitly selected English to the workspace, confirmation/recovery forms, connectivity and skip link. The single selector lives outside every submit form. Locale changes neither remount the business components nor refresh the router, submit consent, re-read workspace data or replay a pending operation. Existing form state, master drafts/caret, tracker drafts/filters, note acknowledgements, cooldowns and recovery stages remain owned by their existing components. Only one exact supported value is accepted; duplicates/unknown/encoded values fall back to Russian. Raw request headers preserve duplicate preference names for this decision. A missing preference can select Russian for display but cannot prove Russian was saved. Blocked/ambiguous storage keeps the current tab usable and shows honest tab-only feedback in both online and offline controls. No live cross-tab synchronization claim is made.

The server layout/metadata use async request headers and dynamic rendering; client lang/title/description/manifest follow the same context. See the [official Next headers contract](https://nextjs.org/docs/app/api-reference/functions/headers). Russian and English manifests retain one id/scope/start URL/icon set. No private values are placed in metadata.

No documents/API/drafts/manifests or private responses are cached or queued. Successful main documents are network-only. Only obsolete app-owned public caches are retired; unrelated caches are retained. Offline code reads/writes the preference only and uses textContent for fixed copy.
