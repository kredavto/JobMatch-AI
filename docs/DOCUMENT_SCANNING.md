# Isolated document scanning and transient quarantine

[PR #78](https://github.com/kredavto/JobMatch-AI/pull/78) above unmerged PR #77; default scanning remains OFF. No production endpoint, flags, keys, SQL or paid resources were provisioned. This is a current implementation, not live host or independent security acceptance.

The optional `worker/compose.antivirus.yaml` overlay makes scanning required. The gateway holds at most one bounded 4,000,000-byte upload in memory. It checks a separately signed observation of the actual loaded ClamAV engine/database, scans immutable bytes using fixed private INSTREAM, checks readiness again, then transmits the same bytes to the private one-job parser. Exact `stream: OK\0` followed by EOF is required; blocked, unknown, stale, untrusted, truncated, oversized, unavailable and timed out responses never reach parser. No inline fallback, retry, filename, client headers or service token is forwarded. Quarantine means transient withholding before extraction, not a persistent forensic store. No rejected file retention or secure-erasure guarantee is claimed.

The trusted observer receives no documents and alone mounts an operator-provided Ed25519 private key. Gateway accepts only canonical Ed25519 PUBLIC KEY SPKI PEM, never private PEM. The signed, strict observation identifies the actual loaded engine, positive database version/time and observation/expiry. Allowed engine is 1.4.6; loaded database age <=24 hours, observation <=30 seconds, actual issued lease 10 seconds; future dates/unknown fields/replays after expiry refuse. Clock/UTC correctness and private service/network ownership are operator requirements. A signature proves the observer assertion, not that the scanner is uncompromised. This is not an attestation bound to each document; a compromised scanner is outside the trust boundary.

ClamAV 1.4.6 LTS is pinned. Source: https://docs.clamav.net/faq/faq-eol.html and official Docker guidance https://docs.clamav.net/manual/Installing/Docker.html (checked 2026-11-01). Version-specific tags are mutable: record the actual tested image ID/digest and loaded database metadata before deployment; do not treat a future build as the tested artifact. npm audit does not assess native OS/image CVEs.

Scanner runs nonroot, read-only root/database, private network, no host port or key, capabilities dropped, NNP, 4GiB RAM/zero swap/1 CPU/64 PIDs; its bootstrap checks actual cgroup v2 ceilings and strips inherited environment before clamd. Observer is 128MiB/.25 CPU/32 PIDs, strict environment allowlist; gateway and parser retain their separate budgets and credential separation. Single scan thread, bounded scan time/depth/count/stream/file sizes, encrypted-content and exceeded-limit alerts are configured. Scanning/OCR remain opt-in; OCR has its own independent flag, limits and review requirements.

A separate FreshClam updater has egress and a writable definitions volume, but receives no documents/key. Scanner gets that volume read-only; concurrent database reload is disabled to avoid double-memory peaks. Keep vendor integrity/database tests enabled. Live reload is observed by scanner VERSION; download file timestamps are not readiness. Update failure or age expiry closes the gate. Preserve existing volumes and updater state; do not delete/reseed data to bypass freshness or CDN limits. New volumes seed the local ZIP policy. Existing volumes need explicit operator provisioning after backup/review: startup requires its bytes to equal the image policy. Never modify vendor definitions to make a test pass.

ClamAV 1.4.6 can truncate a ZIP member at MaxFileSize without its generic exceeded-limit alert. The required local CDB policy therefore blocks declared uncompressed member sizes above 4MiB; boundary and nested-archive tests query the real engine directly, so parser rejection cannot masquerade as antivirus refusal. This local archive policy is separate from vendor malware signatures. Forged sizes, ZIP64/unsupported formats, evasion, unknown malware and complete AV coverage remain open; parser bounds/validation remain independent defense. No antivirus claim means all uploaded files are safe.

Operator setup requires an approved owned HTTPS gateway and PD placement/retention decision, separately supplied gateway token and observer-only key, pinned tested artifact, correct UTC, approved updater egress and managed database/policy updates. Do not generate or print operator secrets through these docs. The private key must not be placed into gateway/parser/scanner environment or images. See `ISOLATED_PARSER.md` and `SCANNED_PDF_OCR.md` for ingress/lifetime/review constraints. No production configuration was changed.
