# Current projection parity preflight

This additive administrative check compares the three legacy workspace payload arrays with five normalized core tables: workspaces, profile_facts, resume_versions, applications and application_events. It also detects missing/excess rows, gaps/duplicate positions, reserved keys or non-object extras, orphan rows and hidden/foreign-owner version associations. Unknown compatibility fields and absent versus explicit-null version links are reconstructed losslessly.

`private.workspace_projection_report()` is SECURITY INVOKER with an empty search path. EXECUTE is revoked from PUBLIC, anon and authenticated; no public RPC or user-facing endpoint is added. It requires full SELECT and refuses an RLS-filtered view even if someone explicitly grants EXECUTE. The function returns aggregate counts only: no owner/entity IDs, text, URLs, receipts, keys or row samples. A zero-workspace result is visible as zero checked rows and is not proof of a populated installation.

The operator CLI is `python3 scripts/check_projection_parity.py`, using standard libpq PG*/PGSERVICE/.pgpass configuration. Credentials must not be put in arguments or checked in. It opens a REPEATABLE READ READ ONLY transaction, sets row_security off and a120-second statement timeout, requires an exact completion marker after COMMIT and validates the closed report schema. Exit0 means no counted drift, exit1 means drift, exit2 means query/permission/protocol unavailability. Errors suppress database diagnostics and unexpected output. It neither repairs projections nor deletes snapshot arrays, changes reads/writes, grants permissions or enables a cutover. An operator must separately approve any production access or rollout.
