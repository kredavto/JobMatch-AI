## Behavior and limits

The API sends only import/fact text or server-owned demo text and vacancy. Client IDs, source labels, verification flags, snapshots and history never enter the command. Direct SQL command shapes reject extras. SQL generates new UUIDs with verified=false, preserves line order and duplicates, and applies the existing CRLF/LF split and ECMAScript trim to derived facts. The original input itself is preserved without normalization. Same-text reimport creates new identities and resets verification, preserving goal, historical versions/evidence/rule metadata, applications and their version links. Manual fact append preserves its exact text and adds one newline to the original. Demo is an unverified raw text/vacancy intent; HTTP uses repository constants, not caller-supplied demo fields.

Existing boundaries are deliberate: raw import is 1–100000 Unicode code points, manual fact 2–2000 code points, maximum 500 facts, but each imported trimmed line retains the legacy 2000 UTF16-unit gate. Installed Zod4.6.7 code-point semantics are tested; private.utf16_length is used only for the legacy imported-line gate. It does not redefine other string limits. NUL/lone surrogates and malformed UTF8 reject before persistence; original whitespace/CRLF/combining/astral text is not silently replaced or normalized.

Owner/session and expected-owner, Origin, quotas and revision gates remain. SQL serializes on the same owner advisory/row locks as legacy and other commands, commits data/projection/audit atomically and returns that transaction's snapshot. Conflict or unknown outcome triggers no retry, snapshot fallback or automatic confirmation. A rejected command does not create a workspace or change history/audit. The compatibility snapshot remains; version/restore commands and normalized read/parity/cutover/array removal are separate next steps. Rollback code can keep additive SQL and use the reviewed legacy writer. No production migration was applied; review actual deployment history before applying an old unmerged migration name.

## Source and letter provenance

A source-backed structured profile is separate from the raw profile/facts. Import or append leaves its stored source/IDs/fields/confirmation intact but makes source_matches=false when the context changes. It cannot silently retarget an old confirmed quote to new text or IDs. Explicit clear remains possible after storage permission is revoked and removes cached source/IDs/entries with a monotonic revision. Reset/add/confirm requires renewed explicit review and storage capability; confirming a field does not verify a legacy fact. Existing immutable letters remain historical evidence; old unaccepted previews fail CAS, and a newly issued current-context preview uses the separately verified current facts. These are deterministic source/CAS guarantees, not model or semantic acceptance.
