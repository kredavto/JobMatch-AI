# Literal structured versions

This additive stage follows PR #19. It creates **separate literal outlines**, not generative rewrites, complete resumes or model-verified qualifications. Match Score, ordinary resume versions, facts and the tracker are not changed. There is no LLM request, email or hh.ru write.

## Review and storage contract

Choose current confirmed structure entries, request preview, inspect omitted information and literal text, then explicitly acknowledge saving that exact outline. Selection changes discard preview/acceptance. Cancel only discards the local preview; preview itself creates no version or business audit. A lost save response blocks further writes until explicit profile reload; reading history/details stays available to reconcile the outcome. No automatic mutation retry occurs. Leaving the page discards draft selection; an already submitted request may still commit, so inspect history on return.

`structured-literal-v1` freezes Russian section/field labels and canonical entry/field order. Quotes, dates and numbers are copied verbatim; no duration, level or extra achievement is inferred. Unselected parts of the resume are omitted. `line-risk-v1` examines every touched source line and conservatively rejects a fixed RU/EN set of negation/planning/instruction tokens. It also examines the prefix/suffix outside a chosen quote and all lines inside a multiline quote. This intentionally rejects some valid statements (e.g. «без ошибок»), is not an NLP contradiction detector, and does not establish semantic truth or correct field classification. Independent model evaluation and generative/letter workflows remain open.

Saved `jobmatch-structured-version-v1` records contain template/context guard versions, generator `literal-template`, explicit `model_version:null`, exact text, selected confirmed entries with Unicode code-point ranges, **full captured source**, ordered source fact IDs, owner and profile/workspace/source revisions, server UUID/date and SHA-256 preview hash. Confirmation/source_matches in this immutable snapshot describes eligibility **at capture**, not the current profile. Reset/reimport/retraction does not overwrite saved versions; reset copy explicitly explains retention. Account deletion cascades them from the active DB. Exported files/backups retain their own copies.

Hash material uses fixed ordered NUL-separated UTF-8 strings: template, guard, generator, `null`, snapshot format, owner, profile/workspace/source revisions, fact-ID count, each fact ID, full source, `true`, rendered text; then each selected entry's ID/kind/exact created string/`true`; for each fixed field title/organization/start/end/description/credential: name, start, end, quote (absent values empty). PostgreSQL cannot store NUL text. This binds preview to provenance and text, including repeated-quote positions; it is not a digital signature or certification. App/browser recheck schema, source slices, render and digest. Historical snapshots remain independently readable after profile changes.

## Database and API

`20261029092404_structured_versions.sql` adds `structured_resume_versions`, FK to workspace (not mutable structure), max 20 versions/owner in the serialized save RPC, unique owner/hash. A BEFORE UPDATE trigger prohibits overwrite, including normal administrator UPDATE; owner/session RLS permits only SELECT; client INSERT/UPDATE/DELETE and anonymous RPC execution are revoked. There is no standalone deletion/overwrite RPC. A database administrator can bypass controls; corruption testing does this **only in a disposable synthetic database**.

Preview/save use the same owner/workspace advisory lock and expected workspace/profile revisions as other writers. Source must still match, all selected IDs must be unique, owned and confirmed. Save recomputes preview under lock and requires its exact hash plus `SAVE_LITERAL_VERSION`; it never accepts caller text/source/template/model metadata. Repeating an identical valid acceptance returns the existing ID without another audit (also at capacity). Changed source/revision/selection/hash rejects. Version insert and static audit are one transaction. Workspace and structure revisions are unchanged by saving.

`/api/structured-versions` POST supports strict preview/save envelopes, same origin, authenticated owner, quota and 10KB UTF-8 body cap. GET returns at most 20 source-free summaries or one validated owner detail; foreign/missing ID yields 404. All responses are no-store, safe errors, with expectedOwner hints checked before access. No service-role secret or direct client SQL write is introduced. Public SECURITY DEFINER wrappers use empty search_path, explicit live session/uid checks in privileged helper bodies and explicit grants; private helpers are not client-executable. Provider advisors and live Auth/PostgREST acceptance remain required before activation; no live schema was changed here.

Settings now require **four downloads**: existing personal JSON, fact-history NDJSON, current structure JSON, all literal-version NDJSON. The personal JSON includes a fourth pointer. These files are not one transactional archive. Version export captures a fixed immutable summary list, reads and validates one detail per pull (new session/quota check per RPC), has a 40MiB total byte cap, and terminates with `complete:true` only after all listed records. Later saved versions require a new export. Failure/revocation/missing/corrupt detail produces `complete:false`; cancellation discards an in-flight result and prevents further reads.

## Verification, installation and rollback

Fresh schema and populated upgrade are tested in PostgreSQL17, including source/context/selection/hash/ack/revision gates, idempotence, immutable/direct-write protections, 20-version cap, audit rollback, owner/session isolation, historical retention and account cascade. A real 20-connection save probe must return one version ID, one row and one audit; independent Python recomputes the native hash. Browser tests are synthetic HTTP fixtures, not live provider proof.

`backup_manifest.py snapshot ... --include-structured` now emits `jobmatch-backup-structured-v4` for **16** tables, including saved literal versions. Compare still accepts historical v3/15-table archives against the same v3 format, but never accepts a missing version table labeled v4 or mixes formats. Default legacy13 remains only for historical migration drills. Native CI seeds all16 tables, performs actual pg_dump/pg_restore, compares all fingerprints, reruns SQL suites, and detects separately changed structure and (administrator-bypassed) version content. This is a synthetic PostgreSQL restore, **not** a Supabase provider backup restore or RPO/RTO evidence.

Apply only after preceding reviewed migrations and explicit deployment approval. Older code can ignore this additive table/RPC without deleting data. Dropping it would destroy accepted versions and needs reviewed export/backup and rollback authorization. This branch does not integrate independent PR #15/#17/#18 or authorize any merge/release. Live model, SMTP/recovery, actual provider restore, operator hosting/privacy/retention, hh.ru permissions and final multi-account/domain acceptance remain open.
