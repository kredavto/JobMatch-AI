# Собственный AI-разбор требований (0.34)

В редакторе после обычного анализа доступна отдельная панель. Пользователь отдельно разрешает один запрос с сохранённой вакансией и подтверждёнными допустимыми фактами. Передаются только id/text фактов, без original, source, email или истории. В тексте вакансии/фактов всё равно могут быть персональные данные: решение о размещении и обработке обязательно.

По умолчанию inference выключен. Настройки только на сервере:

```dotenv
JOBMATCH_AI_ENABLED=false
JOBMATCH_AI_SELF_HOSTED=false
JOBMATCH_AI_ENDPOINT=https://your-own-inference.example/api/chat
JOBMATCH_AI_MODEL=your-reviewed-model
JOBMATCH_AI_TOKEN=
```

Оператор включает оба флага только для собственного проверенного endpoint и модели после оценки размещения, логирования и ресурсов. Не использовать облачный Ollama endpoint: нужен локальный/self-hosted API с поддержкой structured outputs. Production допускает только HTTPS; HTTP loopback — лишь вне production. URL фиксируется оператором, браузер не передаёт endpoint или тексты для подмены серверного snapshot. URL без credentials/query/hash, путь строго `/api/chat`; redirect запрещён. Reverse proxy должен ограничивать доступ и ресурсы. В production обязателен секрет JOBMATCH_AI_TOKEN (16–4096 непробельных символов), передаваемый как Bearer только собственному endpoint. Оператор должен настроить reverse proxy/gateway на проверку этого токена: стандартный локальный Ollama сам по себе такой проверки не обеспечивает. Секрет хранить только в серверной зашифрованной переменной, не в браузере. На Vercel localhost не указывает на внешний сервер модели.

Протокол: Ollama `/api/chat`, `stream:false`, JSON schema в `format`, temperature 0. Схема результата: `{requirements:[{quote,evidence_ids}]}`. Цитата должна дословно присутствовать в вакансии, IDs — однозначно ссылаться на подтверждённые допустимые факты. Повторы и дополнительные поля отвергаются. До 50 требований и 20 ссылок на каждое; 48 КБ входа, 64 КБ ответа, общий timeout 20 секунд, без автоматического retry.

Это предложения связей для ручной проверки. Точные цитаты и IDs доказывают происхождение, но не семантическую релевантность. Модель может ошибаться или следовать инъекции; результат не меняет score, профиль или сохранённую версию. Полноценное переписывание/AI scoring и структурированный профиль ещё не реализованы. Результат хранится в памяти панели и сбрасывается при смене ревизии/владельца/выходе.

Endpoint POST `/api/ai-review`: same-origin, текущая сессия, обязательные consent/expectedOwnerId/revision, PostgreSQL analysis quota. Клиент повторно проверяет владельца, ревизию и цитаты. Ошибки провайдера скрыты; no-store; модель не вызывается без конфигурации и согласия. Нет передачи в сторонний LLM по умолчанию. Локальная квота не заменяет ограничение ресурсов самого inference-сервера.

Проверки: unit/route и локальный HTTP fixture проверяют интеграционный контракт; браузер использует mock ответа AI. Настоящая модель и её качество этим не проверены. Для включения нужен живой набор RU/EN примеров, включая негативные и противоречивые факты, годы/уровень, составные требования, чужие/отозванные IDs, prompt injection и отсутствие свидетельств.

Официальные источники контракта, проверены 28 октября 2026:
- https://docs.ollama.com/capabilities/structured-outputs
- https://docs.ollama.com/api/chat


## Подготовленный оценочный CLI (29 октября 2026)

`evaluation/README.md` описывает запуск на собственном согласованном endpoint и ограничения. Встроены 28 синтетических RU/EN cases с строгими gold quotes/IDs и отказом пустому/неполному результату. CLI не включает AI сам, не читает профили/БД и не принимает файлы пользователя. Обязательны отдельный `JOBMATCH_AI_EVAL_APPROVED=true` и operator-declared digest. Report не содержит сырых ответов/фактов/токенов и прямо отмечает `modelIdentityVerified:false`.

Prompt `requirements-evidence-v2` теперь требует, чтобы совокупность связанных фактов обосновывала целое требование, включая длительность/числа/уровень; при недостатке/противоречии — пустые IDs. Provenance gate не доказывает исполнения этих инструкций. Модель, endpoint и семантическое качество пока не проверены: scripted HTTP fixtures подтверждают только harness/протокол/отказы. Успех синтетического gold-набора не закрывает независимую живую приёмку.
