# Команды импорта и фактов

Зависимый этап после PR #4 переводит `POST /api/service` для import/demo/fact на `apply_workspace_command`. API передаёт текст намерения и ревизию, без чтения/записи полного профиля. SQL читает snapshot только текущего владельца под той же блокировкой, что и legacy writer, и возвращает результат своей транзакции с `revision + 1`.

## Контракт RPC

| action | Поля команды | Результат |
| --- | --- | --- |
| `import` | `text`: 1–100000 Unicode code points | Точный original, заново созданные неподтверждённые факты, пустая vacancy |
| `demo` | `text`: 1–100000 code points; `vacancy`: 5–30000 code points | Новый неподтверждённый профиль с заданной вакансией |
| `fact` | `text`: 2–2000 code points | Один неподтверждённый факт; exact text добавляется к original через LF |

HTTP action demo использует существующие серверные константы демонстрации и игнорирует text/vacancy клиента. Прямой аутентифицированный RPC может передать допустимые text/vacancy; они также становятся только неподтверждённым профилем. Это не доверенный источник и не независимая проверка фактов.

ID, source и verified создаёт SQL. Source импорта/демо — «Введено пользователем», source добавленного факта — «Уточнение пользователя», verified всегда false. Неизвестные поля RPC, включая массив facts, ID, source, verified и владельца, отклоняются. HTTP отбирает только допустимые поля намерения.

## Паритет прежнего поведения

Импорт делит строки по CRLF/LF, обрезает крайние символы по правилам ECMAScript trim и пропускает пустые строки. Дубликаты и порядок сохраняются. Одиночный CR внутри строки остаётся частью текста. Исходный original хранится точно, включая пробелы и переносы. Непустой ввод только из пробельных символов по-прежнему допустим и даёт пустой список фактов.

Каждый импорт, даже того же текста, создаёт новые UUID; прежние подтверждения не переносятся. Сохранённые версии резюме, evidence_snapshot, отклики и их связи, goal и неизвестные поля совместимости сохраняются. Состав фактов и подтверждения фиксируются существующей историей и реляционной проекцией в той же транзакции.

Отдельный fact не делится на строки и не обрезается: он сохраняется дословно и добавляется к original через LF. Общий предел — 500 текущих фактов. Импортированные строки ограничены 2000 UTF-16 единицами, как в прежней ручной проверке JavaScript .length; raw text и отдельно добавленный fact ограничиваются code points, как в текущем Zod. Supplementary Unicode symbols могут поэтому иметь разные допустимые границы при импорте строки и отдельном добавлении. Глобальные ограничения commit gate сохраняются.

Превышение любого лимита, неверная ревизия и отозванная сессия не сохраняют частичного результата. Конфликт/неоднозначный сбой не вызывает автоматический повтор или fallback на snapshot. Доступ к новым helper-функциям private закрыт для public/anon/authenticated; SECURITY INVOKER и пустой search_path сохранены.

## Выпуск и откат

1. Сначала объединить и принять PR #4; затем этот зависимый этап. При выпуске проверить актуальный base и весь набор миграций.
2. После предыдущих миграций применить `20261028110002_profile_import_commands.sql` до API-кода.
3. Выполнить SQL-suite в изолированной тестовой базе и живой сценарий импорта с тестовым аккаунтом перед выпуском.

Legacy `save_workspace` остаётся совместимым: при откате приложения новое SQL-расширение можно оставить. Снимать расширение при работающем новом API нельзя. В консолидированной schema.sql сохранён тот же порядок стадий. Дублирующие JSON-массивы пока остаются; команды version/restore и удаление snapshot — отдельные задачи. Извлечение текста из файлов в `/api/import` этим этапом не меняется.
