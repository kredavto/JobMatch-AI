# Подтверждение опыта из требований
Кандидат изменения, 30 октября 2026.

- В таблице требований показываются тексты подтверждённых evidence, а не только ID.
- Связанные неподтверждённые исходные строки доступны в раскрываемом блоке. Поиск использует текущий консервативный словарь и точное совпадение; это не семантическое доказательство.
- Кнопка «Подтверждаю весь факт» подтверждает только выбранный факт через существующую серверную команду verify. Автоматического подтверждения и массового принятия нет.
- После успешного сохранения серверный анализ вызывается с новой revision; ответ проверяется относительно возвращённого снимка. Выбранные правки сбрасываются.
- Ошибка/конфликт не вызывает автоматический повтор записи и не повышает балл. Ошибка повторного анализа не скрывает факт уже сохранённого подтверждения.
- Отрицания, планы обучения и инструкции не предлагаются для быстрого подтверждения. Несоставленные в словаре связи уточняются вручную в профиле.
- Подтверждение B2B не доказывает длительность стажа, уровень или выполнение составного требования.
- Изменение не добавляет переписывание текста, структурированный импорт, автоматическую интеграцию hh.ru или независимую верификацию квалификации.

Проверки: unit-тесты поиска кандидатов и сохранения консервативного score; Playwright на вымышленном профиле — явное подтверждение, новая revision, пересчёт, отдельная версия, TXT, повторное открытие, отказы 409/503, WCAG tags таблицы. Результат CI фиксируется в PR после завершения. Production этим документом не считается обновлённым.


## Интеграция с текущей веткой, 30 октября 2026
Кандидат поверх #40 переносит техническое содержимое #37, сохраняя глобальный RU/EN выбор, typed feedback и source/owner/revision gates. Строки evidence/candidate показываются дословно, known rule reasons переводятся только для отображения. Подтверждение относится ко всей строке; совпадение терминов не доказывает требование, срок или уровень.

До установки ответа verify проверяются известный тот же owner, ровно revision+1 и точное единственное изменение verified выбранного fact ID. Другие факты, порядок, исходники, цель, версии, отклики и неизвестные поля не должны изменяться. Ошибка не устанавливает снимок и не запускает анализ. Это дополнительная проверка ответа клиента, не авторизация БД; серверные origin/session/expectedOwnerId/command gates сохраняются.

После успешного verify анализ использует возвращённый проверенный снимок и его revision/owner. Ответ пересчитывается/сравнивается через текущий rules-v1 validator. Выбранные edits/history сбрасываются. Синхронный pending guard закрывает повторное подтверждение. Нет автоматического повтора записи после ошибки или потери ответа.

Новый черновик resume/vacancy, введённый во время verify, сохраняется; анализ откладывается с явным сообщением, что факт уже подтверждён и сохранён. Ошибка/подмена повторного анализа также сохраняет это различие: подтверждение состоялось, нового проверенного score нет. Позднее завершение не меняет выбранную вкладку. Уведомления хранят semantic key/score params и переводятся при смене locale без нового запроса; раскрытый candidate блок переживает смену языка.

Неизвестный owner, paused/reload state, busy и dirty source блокируют быстрое подтверждение. Profile navigation остаётся ручной. Actual Next browser tests используют synthetic API replies; unit tests проверяют строгий ack, обе локали и conservative matching. Ни настоящая независимая проверка опыта, ни live model/SMTP/provider restore/финальная приёмка этим не доказываются.
