# Full-resume Groq pilot: inactive integration candidate

Base: Preview e10909c. Supersedes the isolated selected-snippet/per-send-consent prototype, which is NOT included in this branch.

User direction: full resume text, one affirmative consent reusable for subsequent user-started adaptations; Groq is the named recipient. This candidate implements state and contracts only, with injected mock transport. It is not installed in Home or any public API route. Feature defaults OFF. Saving consent, page load and reload never send a request.

## Browser consent and review

The inactive mobile-styled component shows the complete current source text and an affirmative unchecked consent control. Stored record contains only random consent ID, policy/recipient/browser-scope, grant state and timestamp, never resume text. It persists for this browser only; shared-device warning is mandatory. Changes to recipient or disclosure require a new policy version; old/invalid records fail closed. Revocation updates the record and cancels/discards current work; storage events revoke/invalidate other open instances. Write failures block requests in the current component and explicitly do not claim successful revocation. This is optimistic storage, not atomic cross-tab authorization.

Only the explicit adaptation button invokes the session. Changing the source remounts/cancels the instance; changed consent snapshots discard late responses, even if a storage event was missed. Past transmission cannot be undone by cancellation or revocation. The source and deterministic result remain unchanged. Suggested facts use the existing side-by-side review panel and cannot be applied automatically.

The consent notice discloses full-text transmission to Groq, possible US processing/retention, unverified ZDR, recurring use and revocation. Ordinary names and contact text are not silently removed. Known credential, document, SSN/long-number and health-label patterns are blocked before mocked transmission and rechecked at ingress. This is NOT comprehensive detection, anonymization, a legal compliance assessment or proof that a resume is safe. Obfuscated identifiers, personal facts and unrecognized sensitive content can evade it; legitimate numeric text can be rejected. Never use tests as permission to transmit critically sensitive data. User review/removal of excess sensitive information remains necessary.

## Server and operational boundary

`createFullResumeRewriteHandler` is a factory, not a deployed route. Enabling it without both authorization and provider dependencies still returns 503. It requires exact same-origin POST, strict versioned consent shape, body <=50KB, resume <=10,000 characters, <=80 source lines with <=2,000 characters each (no truncation). Full resume alone reaches the injected provider; request ID and consent stay outside that input. Unknown vacancy/profile fields and old policy are rejected. Responses are private/no-store; errors contain no raw body or provider messages. Lexical/source validation remains insufficient to guarantee meaning.

The required `authorizeAndReserve` must independently authenticate a restricted pilot, check entitlement/consent where supported, atomically deduplicate request IDs and reserve durable global+user spend limits across Vercel instances. Client consent, same-origin, environment flags and in-memory throttles are not substitutes. The HTTP-layer limiter is in-memory. The SQL schema also includes authenticated atomic `consume_quota` for service/import/analysis (120/10/20 requests per minute per user), but no global monetary/token budget, rewrite idempotency reservation or restricted-pilot entitlement. Its deployed state has not been checked. Reusing auth plus a separately reviewed durable rewrite reservation is a plan, not configured functionality. Existing Preview protection must also be verified before relying on it; protection alone is not a spend limit. No new auth or infrastructure is configured here.

Provider adapter must use fixed Groq destination/model, bounded output, strict schema, no retry/streaming/tools, request timeout and abort-aware transport. The handler also stops waiting after 15 seconds, but cannot force an uncooperative adapter to stop spending. The pinned adapter now exists but is not connected to a route, environment or real credential. `createGroqFullResumeAdapter` requires injected fetch/key, uses exactly `https://api.groq.com/openai/v1/chat/completions`, `openai/gpt-oss-20b`, synchronous strict JSON Schema, 2,048 completion-token ceiling, no tools/redirects/retries, 15-second signal and 64KiB response ceiling. It is single-attempt per instance, NOT a global spend limit. Its response still passes source/lexical validation. All adapter tests use a fake key and mocked fetch.

Official references checked November 19: [Groq strict schema](https://console.groq.com/docs/structured-outputs), [GPT-OSS 20B](https://console.groq.com/docs/model/openai/gpt-oss-20b). Schema guarantees only structure, not semantic fidelity.

## Isolated browser harness and follow-up review

`playwright.full-resume.config.ts` runs only `tests/e2e/full-resume-pilot.spec.ts` against a dedicated loopback Vite server under `tests/fixtures/full-resume-browser`. It requires an explicit synthetic-harness flag, disables env-file/public-folder loading, imports no provider adapter, and uses a fixed browser mock. It is not a Next route or public asset. Isolation tests assert app/public sources do not import it or expose its synthetic markers. The three browser cases cover initial unchecked consent, reload persistence, two user-triggered launches, revocation, absent vacancy metadata, local fallback, private diagnostics and late response invalidation at 390×844.

An actual local Playwright attempt failed before navigation: system Chromium `process_singleton_posix.cc:297 socket() failed: Operation not permitted`. No escalation/bypass used. The three tests are authored, NOT browser-verified. A same-process loopback probe successfully served the transformed synthetic entry module (HTTP 200); a cross-command probe was refused. Neither probe substitutes for browser execution.

Provider request minimization: resume appears once, plus opaque source IDs and UTF-16 character ranges (no duplicate source text). Server retains source mapper for exact quotation validation. Groq receives no vacancy/title/requirements and only performs generic language cleanup; existing deterministic adaptation retains vacancy targeting locally. Do not advertise model-informed vacancy matching.

Multi-user release blocker: current browser-scope consent is NOT tied to an authenticated subject. Before a shared/multi-account pilot, bind consent to a server-verified subject and invalidate on logout/account change; do not accept a client owner hint. Root checked Preview is public (SSO/password protection disabled); therefore route must remain default-deny. No auth/quota infrastructure has been enabled. Existing browser consent is only a disabled prototype, not an account-safe release gate.
