# Structured UI localization (RU/EN preparation)

This stage follows PR #22 and extracts all presentation copy from StructuredProfilePanel, StructuredVersionPanel and SavedRemindersPanel into typed RU/EN catalogs. Shared keys/interpolation parameters and domain-key label maps are checked by TypeScript. Schema modules no longer export unused Russian UI labels. The three actual components accept an optional locale prop, default Russian; nested literal-version UI receives the same locale. Component roots mark their interface language. No production route, cookie, language detection, context or language switch exposes an incomplete English application.

## Data and command boundary

Only labels, hints, validation feedback, status/action display and display dates are localized. Canonical kind/field/status/action values, IDs, revisions, source offsets, acceptance literals, source quotations, user titles/descriptions, original resume text, JSON snapshots, filenames, saved literal text and preview hashes remain unchanged. No UI locale is added to API commands. There is no translation request to an LLM or another service.

The existing structured-literal-v1 template has frozen Russian field labels. Its **saved output is not translated** by an English interface. Both languages explicitly explain this. An English document template would require its own version/provenance/acceptance; this change does not relabel old versions or claim a new model/template. Date/number quotations selected from a resume remain literal and are never passed to display-date helpers.

Feedback is stored as semantic state or RequestError/code, not a previously translated string. Task success notices distinguish create/update/complete/cancel/delete (deleting no longer says “saved”). Changing locale re-renders notices, local validation failures and API feedback without replaying requests, resetting drafts/selection/preview/acceptance, changing revisions or resubmitting writes. Late replies to in-flight requests use the current display locale. Existing owner/source/revision checks, lazy/manual reads, synchronous duplicate guard, abort/unmount behavior and no-retry conflict recovery remain intact. Unknown local exceptions use a fixed unverified-response message, not raw diagnostics. Legacy API errors still follow the bounded RU/EN fallback described in API_ERROR_CODES.md.

## Dates and historical zones

`i18n/dates.ts` validates ISO input and formats instants with an **explicit** zone (UTC by default), ISO calendar, Latin digits and a 24-hour clock. It never silently uses the device zone. The chosen zone is included in displayed text. Machine ISO strings remain in `<time datetime>` and in unchanged exports. Invalid dates/zones produce localized invalid-date copy instead of plausible normalized dates.

Accepted task wall time is formatted from persisted dueLocal and offsetMinutes, not by recomputing dueAt using today's IANA rules. Offsets show exact signed hours/minutes (UTC+05:45, UTC+10:30), not fractional hours. The UTC instant is displayed separately. Historical unavailable/different zone rules produce a localized warning while the accepted wall time/offset/UTC remain readable. Nothing is rescheduled by rendering. Overdue state still uses the server timestamp from the captured list, which is now formatted with UTC and a visible refresh hint.

User/source text is rendered literally. Unknown-language content is marked separately from interface copy; this is not language detection or a guarantee of screen-reader pronunciation. Source ranges are separated visually from their quotations. Layout can wrap long labels/content without changing bytes, field values or source offsets. Manual screen-reader/physical-device acceptance remains open.

## Verification boundary

Unit tests check explicit zones, RU/EN display, minute offsets, invalid dates, accepted-wall semantics, domain-key maps, frozen text/hash, relocalized feedback and safe locale fallback. Existing Russian app browser tests remain applicable; the saved-task timestamp assertion now checks its unchanged machine datetime instead of requiring a raw ISO string as UI copy.

New browser tests bundle the **actual production components** into an isolated ephemeral loopback fixture using pinned dev-only esbuild0.28.2. The fixture is test code, not an application route or a shipped English screen. It uses the real React components/validators/export/hash code with synthetic HTTP responses; it does not authenticate to Supabase or prove provider behavior. Official bundler API checked29Oct2026: https://esbuild.github.io/api/ and https://esbuild.github.io/content-types/ . Bundle output stays in memory; server/connections/compiler are closed after tests. No production bundler, runtime dependency or application route is changed; esbuild is a direct dev dependency/lockfile entry for reproducible fixture builds with npm ci --ignore-scripts.

RU/EN workflows assert identical owner/revision/command payloads, emoji UTF-16→code-point capture, separate confirmation, literal preview/save and equivalent decoded exported JSON and unchanged source/text/hash. Tasks render 10:30 UTC+03:00 and07:30 UTC even with the browser device zone set to America/Los_Angeles. Tests cover unavailable historical zone metadata, drafts and selection across locale changes, and changing locale while a write is in flight without a second mutation. Mobile axe/overflow checks and screenshots complement the existing Russian UI regression. These checks do **not** establish full-app English acceptance, real model quality, SMTP delivery or provider restore.
