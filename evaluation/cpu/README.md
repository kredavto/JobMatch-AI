# Настоящая CPU-диагностика на синтетическом корпусе

Кандидат PR #47 выполняет **локальную inference реальных весов** в одноразовом existing GitHub Actions runner. Это отдельный технический диагностический путь, не опубликованный inference service, не одобренная модель и не финальная приёмка. Bridge tests и actual model execution показываются раздельно.

## Источники, стоимость, права

Репозиторий публичный. [GitHub standard runners](https://docs.github.com/en/actions/reference/runners/github-hosted-runners) описывает ubuntu-24.04 как стандартный Linux4CPU/16GB runner с бесплатным использованием в публичных репозиториях. Job отказывается запускаться для private/forked repository и использует только contents:read. Нет larger/GPU/self-hosted runner, registry publication, paid service, model cache или artifact upload. Эти условия нужно перепроверять перед переносом в другой/private repository; технический pipeline не подтверждает состояние будущего биллинга.

Qwen/Qwen2.5-0.5B-Instruct-GGUF — официальный публичный источник. Pin `df5bf01389a39c743ab467d734bf501681e041c5` включает LICENSE Apache-2.0 и наследует weights upload `6dd44a1fb35d11b5d1b28902876ce3cc9e882d0e`. Файл qwen2.5-0.5b-instruct-q8_0.gguf: ровно675710816 bytes и SHA256 ca59ca7f13d0e15a8cfa77bd17e65d24f6844b554a7b6c12e07a5f89ff76844e. [Published pointer](https://huggingface.co/Qwen/Qwen2.5-0.5B-Instruct-GGUF/raw/main/qwen2.5-0.5b-instruct-q8_0.gguf), [license commit](https://huggingface.co/Qwen/Qwen2.5-0.5B-Instruct-GGUF/commit/df5bf01389a39c743ab467d734bf501681e041c5). Runtime не использует main: downloader сверяет exact pointer/size/hash по immutable revision, скачивает LICENSE и требует exclusive new output directory. Неверный размер/digest, insecure/foreign redirect, deadline или незавершённый файл дают отказ; существующие данные не перезаписываются. Download не вызывает inference API и не принимает caller URL/token.

llama.cpp source pin `8642541b255bfb5dc39cd351a178be09013a55d6` (release v0.8.0): [source](https://github.com/ggml-org/llama.cpp/tree/8642541b255bfb5dc39cd351a178be09013a55d6), [server contract](https://github.com/ggml-org/llama.cpp/blob/8642541b255bfb5dc39cd351a178be09013a55d6/tools/server/README.md). Собирается CPU binary, UI build/download и SSL отключены; runtime network namespace отдельно закрывает внешнюю сеть. Source и weights зафиксированы; base node:24-bookworm/apt toolchain не являются bit-reproducible pins. Поэтому сохраняются фактические container image ID, binary SHA256, Node/CPU metadata; повторяемость качества между разными CPU/компиляторами не обещается.

## Границы исполнения

Фазы download/build имеют сеть только для публичных dependencies/weights/source. Inference container запускается с --network none, read-only root/repository/weights, cap-drop ALL, no-new-privileges, uid1000,4CPU/4GiB/128PIDs,64MiB noexec tmpfs и внешним900s deadline. Docker socket, secrets, provider credentials и production .env не передаются; checkout persist-credentials=false. Сервер слушает только loopback, offline/no-webui, model path фиксирован, ctx4096/parallel1/threads4/seed42/temperature0/max_tokens2048. Не предусмотрен произвольный endpoint/model/corpus/файл пользовательских данных. Это CI изоляция; она не заменяет аудит безопасного production размещения PII.

Node проверяет size/read-only mode/SHA256 веса перед стартом и после прогона; сам запускает server с этим exact path. Это executionBinding=readonly-file-and-owned-local-process, **не cryptographic attestation реально загруженных весов удалённого deployment**. weightsFileVerified=true относится к файлу. deploymentIdentityVerified=false и исходный evaluator modelIdentityVerified=false сохраняются. /health показывает готовность процесса, а не качество или identity модели.

Существующий evaluator вызывается отдельным процессом с очищенным окружением и прежними28 synthetic RU/EN cases, prompt requirements-evidence-v2, filtering/provenance validator и20s/provider/600s total deadlines. Bridge принимает только точные system/schema/options и bundled synthetic user inputs, с конечной multiplicity для одинаковых RU/EN inputs. Он преобразует транспорт /api/chat→/v1/chat/completions/обратно, не читает gold expected, не заполняет пустой ответ, не чинит JSON/цитаты/IDs, не делает retries. Non-stop/length/zero-token/invalid/oversized upstream результаты не становятся успешным stop. Одновременный/лишний/чужой input отвергается; client disconnect отменяет backend request. Native-model stdout/stderr и raw outputs в отчёт не попадают.

## Что означает результат

Исторический V1 сохраняется в отчёте #47. В #48 новый safe JSON использует prefix JOBMATCH_CPU_DIAGNOSTIC_V2/format jobmatch-cpu-diagnostic-v2 и опциональный evaluator schema2 с error stage counters ([контракт](../FAILURE_STAGES.md)). JSON содержит pins/file/binary/image/runtime, число accepted/backend responses/generated tokens/finish statuses, CLI exit/quality и прежние per-case grade/error counters, corpus/prompt versions/hashes. Только синтетические данные; нет endpoint/token/prompt/facts/raw completion/provider diagnostics.

Чтобы диагностический процесс завершился успешно, нужны completed28 и хотя бы один подтверждённый backend response с положительным token count. Ошибки отдельных requests/проверки provenance и gold mismatches сохраняются. CI green означает **завершённую диагностику**, не качество или готовность модели: acceptance=not-accepted всегда. Отдельно читаются evaluation.passed/errors/rows, evaluatorExitCode и diagnosticQuality. 28 contract failures или quality mismatches нельзя назвать принятой/проверенной для продукта моделью. SIGTERM/startup/hash/network/provider interruption не превращаются в пустой успешный report.

Small synthetic exact-gold smoke не является independent held-out RU/EN evaluation; score/семантическая истинность/противоречия, реальные документы, нагрузка, reproducibility и ручная приёмка не закрыты. Не включать production AI по результату этого workflow.

## Запуск и регрессия

Новый PR с executable changes запускает guarded standard job. Отдельные tests: npm run test:ai-evaluation (17 scripted/native transport harness cases, не модель), Python downloader/scope tests. На final docs-only head scope gate явно пропускает **повторный** model run; это не свежая оценка. Git/event/output failure даёт отказ с кодом2 без skip decision. Пустой diff и manual workflow_dispatch требуют model run. Исходный runtime run/hash должен сохраняться в VERIFICATION и отчёте; docs-only статус не заменяет его.

Workflow не публикует веса/artifacts и удаляет только свой временный каталог. Остановка/удаление контейнера завершает owned processes. Код не меняет app AI config/флаг, разрешения Supabase, почту, hh.ru или deploy/release.
