# JobMatch: простой MVP

Один экран, четыре действия: загрузить исходное резюме → загрузить ссылку → адаптировать → выбрать резюме из списка hh.ru. Последний шаг подготовлен в интерфейсе, но недоступен до реального подключения hh.ru; вымышленные резюме не показываются. Перед ним размещён переход «Войти в hh.ru» на настоящую страницу https://hh.ru/account/login в новой вкладке. Открытие/возврат из этой вкладки не считается авторизацией JobMatch: чтение пользовательской сессии ещё не реализовано, список остаётся заблокирован. Пароли и коды приложение не принимает. Сопроводительное письмо создаётся вместе с резюме для ручного отклика.

## Что работает

- PDF с текстовым слоем и DOCX: до 4 000 000 байт, PDF до 30 страниц. Сканам нужен предварительный OCR; старый Word `.doc` нужно сохранить как `.docx`.
- Публичная HTTPS-страница вакансии: JobPosting JSON-LD или явные `h1` и `main`/`article`. Закрытые сайты, CAPTCHA и страницы без доступного описания не обходятся.
- Точное название вакансии в заголовке результата. Релевантные фрагменты берутся из исходного резюме, оригинальные сведения сохраняются. Отсутствующие навыки не объявляются навыками кандидата.
- Загрузка файла остаётся источником опыта. Будущий выбор из списка hh.ru определит резюме в аккаунте, в которое будет переноситься результат. Кнопка скачивания и выбор формата убраны по новому запросу. Ранее реализованный экспорт DOCX/PDF сохранён в API, но не используется новым экраном.
- Нет аккаунта JobMatch, БД, истории, ручных подтверждений и трекера в новом сценарии. Файлы обрабатываются сервером в памяти; результат живёт во вкладке до закрытия. Не используйте реальные документы для технических тестов.

## Текущие ограничения

**Живой AI не подключён.** Без включённой модели используется честно обозначенная «Автоматическая адаптация»: точные совпадения навыков и выбор исходных фрагментов. Это не генеративная перепись. Подготовлены адаптеры собственной модели Ollama и Vercel AI Gateway. Они выбирают только индексы исходных фрагментов и не создают новые квалификационные утверждения. Ошибка или неполная настройка включённой модели теперь возвращает явную ошибку, без подмены автоматическим режимом.

**Импорт hh.ru не включён без зарегистрированного доступа.** Проверка 8 ноября 2026: текущая официальная OpenAPI для GET `/vacancies/{vacancy_id}` наследует OAuth security; анонимный пробный запрос вернул 403. Это не доказывает причину отказа. Условия API требуют регистрации приложения. Настроенный импорт читает только официальный API, не публикует резюме и не отправляет отклики. Доступность записи резюме/откликов не подтверждена.

Автопилот через браузер без API не реализован. Приложение не принимает и не хранит логин/пароль hh.ru, не входит в аккаунт, не сохраняет резюме и не отправляет отклики. [Соглашение hh.ru](https://hh.ru/account/agreement) ограничивает передачу учётных данных, ПО, имитирующее действия соискателя, и автоматический сбор данных. Нужен разрешённый платформой путь; обходы защиты не используются.

Источники: [OpenAPI](https://api.hh.ru/openapi/specification/public), [метод вакансии](https://api.hh.ru/openapi/redoc#tag/Vakansii/operation/get-vacancy), [условия HH](https://dev.hh.ru/admin/developer_agreement).

Ограничения размера, времени, параллельности и частоты запросов действуют на экземпляр приложения. Это не распределённая защита от злоупотреблений. PDF/DOCX обрабатываются внутри serverless-процесса, без изолированного антивирусного worker. Для открытого массового сервиса нужны отдельная эксплуатационная и правовая приёмка. В текущем Vercel-проекте регион `fra1`; соответствие требованиям обработки персональных данных в РФ не подтверждено.

## Запуск

Node.js 24:

```sh
npm ci
npm run dev
```

Для простого сценария Supabase не нужен. Старые модули и миграции оставлены в репозитории для совместимости и не подключены к новому экрану. Эта ветка начинается от `main`, не сливает накопленную цепочку старых PR.

## Подключение собственного AI

Настройте секреты на сервере, не в клиенте и не в Git:

- `JOBMATCH_AI_ENABLED=true`
- `JOBMATCH_AI_SELF_HOSTED=true`
- `JOBMATCH_AI_ENDPOINT=https://YOUR-OWN-SERVICE/api/chat`
- `JOBMATCH_AI_MODEL` — модель с JSON schema output
- `JOBMATCH_AI_TOKEN` — токен защищённого шлюза

После настройки отдельно проверьте реальную модель на синтетическом резюме. Без такой проверки готовность AI не заявляется. Сторонний провайдер и передача ему персональных резюме автоматически не подключаются.

Для HH нужны согласованные регистрация/условия и серверные `JOBMATCH_HH_VACANCY_IMPORT=approved`, `JOBMATCH_HH_USER_AGENT=App/1.0 (contact@example.com)`, `JOBMATCH_HH_APP_ACCESS_TOKEN`. Не включайте флаг вместо реального доступа.

Новый E2E использует синтетическое резюме, настоящие import/adapt API и смоделированный ответ источника вакансии. Реальные AI/HH вызовы не имитируются как успешная интеграция. Старые unit/E2E suites сохранены отдельно и не являются приёмкой нового экрана.

## Мобильный запуск

Адаптивный экран и PWA manifest позволяют добавить JobMatch на главный экран и запускать отдельно от вкладки браузера. На мобильном при первом открытии видна кнопка «Создать ярлык приложения». Android/Chromium показывает системный диалог только после события `beforeinstallprompt` и нажатия пользователя; если браузер его не предоставляет, показан путь через меню. На iPhone/iPad показаны шаги Safari «Поделиться → На экран Домой». Приложение не может самостоятельно открыть системный диалог iOS. В установленном режиме подсказка скрыта.

Manifest задаёт стабильный `id`, `scope`, `start_url: /`, `display: standalone`, PNG-иконки 192/512 и Apple touch icon. Ярлык относится к тому домену, с которого его установили; для проверки preview используйте постоянный адрес ветки, а не одноразовый адрес сборки. Для работы нужен интернет. В Cache Storage находятся только четыре фиксированных публичных файла (офлайн-страница и иконки); резюме, сессии, API и персональные страницы туда не записываются. Загруженные данные не сохраняются между запусками.

Короткие мобильные E2E проверяют макет, iOS-инструкцию, обработку синтетического события Android, standalone и manifest. Это не заменяет проверку установки на физическом устройстве.

## Подготовленный Vercel AI Gateway

Ветка содержит выключенный по умолчанию адаптер настоящей модели `openai/gpt-4.1-mini`, проверенной в каталоге Gateway 08.11.2026. Это не свидетельство успешного живого вызова: доступ и баланс команды ещё не проверены. Текущий статус доступен в `/api/mvp/capabilities` и виден на главном экране.

После отдельного согласования получателей данных и бюджета владелец может настроить в нужном deployment:

- `JOBMATCH_AI_ENABLED=true`
- `JOBMATCH_AI_PROVIDER=vercel-gateway`
- `JOBMATCH_AI_GATEWAY_APPROVED=true` — операционный флаг, не замена согласия владельца или пользователей.

На Vercel используется токен текущего запроса через официальный `getVercelOidcTokenSync()`. Приложение не создаёт ключи, не запускает CLI-вход и не обновляет локальные credentials. Вне Vercel потребуется заранее разрешённый `AI_GATEWAY_API_KEY`, переданный безопасным способом, не через чат или Git. Токены не возвращаются клиенту и не журналируются.

Запрос идёт только в Vercel AI Gateway с провайдером `openai`, без перенаправлений, инструментов, переключения провайдера и автоматического повтора. Модель семантически выбирает до пяти подтверждённых исходным текстом фрагментов; приложение сохраняет оригинал и использует эти фрагменты в резюме и коротком письме. Модель не дописывает квалификации. При ошибке настроенной модели возвращается понятная ошибка, а не шаблонный результат под видом AI.

Перед публичным включением нужны согласованный лимит расходов в Gateway, защита от злоупотребления платным endpoint и разрешение на обработку данных. Текущий локальный rate limiter не является глобальным финансовым лимитом serverless-развёртывания. Сначала достаточно одного отдельно разрешённого теста на синтетическом резюме в изолированной проверке. Не включайте публичный платный режим только ради такого теста.

Документация: [OIDC](https://vercel.com/docs/ai-gateway/authentication-and-byok/oidc), [каталог моделей](https://ai-gateway.vercel.sh/v1/models), [бюджеты](https://vercel.com/docs/ai-gateway/observability-and-spend/budgets).
