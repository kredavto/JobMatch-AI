# Groq: изолированный синтетический тест

## Статус на 8 ноября 2026

В браузере владельца на Mac подтверждён Free tier. В Groq Playground выполнен живой запрос к `openai/gpt-oss-20b` на встроенной синтетической паре: temperature 0, max 1 024, reasoning low, JSON mode. Получен `{"indices":[0,1,2,3]}`: выбраны исходные положительные факты без отрицания Kubernetes, изучаемого Docker, нерелевантной строки и инструкции добавить AWS. Это один успешный пример, не оценка качества на реальных резюме.

**API strict schema ещё не проверена живым вызовом.** Ветка содержит серверный адаптер Groq и тесты с подставленным транспортом. Playground JSON mode, изолированный API smoke test и E2E приложения — разные проверки; успешный Playground не заменяет две последние. Код этой интеграции не создаёт аккаунты, ключи и платежи, не переключает тариф и не включает deployment. Настройка секретов выполняется отдельно владельцем/уполномоченным оператором.

## Проверенные публичные условия

- [Free tier](https://console.groq.com/docs/rate-limits): для `openai/gpt-oss-20b` и `openai/gpt-oss-120b` опубликованы 30 запросов/мин, 1 000/день, 8 000 токенов/мин и 200 000/день. Срабатывает первый достигнутый предел. Ограничения общие на организацию; фактические значения нужно проверить в её консоли.
- [Structured Outputs](https://console.groq.com/docs/structured-outputs): обе модели поддерживают `strict: true`. Для маленького теста выбран `openai/gpt-oss-20b`. OpenAI здесь является разработчиком открытой модели, а API-запрос идёт непосредственно в Groq.
- [Оплата](https://console.groq.com/docs/billing-faqs): переход на Developer требует платёжного метода и включает тарификацию. Не переходить на платный план и не добавлять способ оплаты для этого теста.
- [Обработка данных](https://console.groq.com/docs/your-data): обычные inference-запросы по умолчанию не сохраняются, но возможны журналы ошибок/злоупотреблений до 30 дней; сохраняемые данные размещаются в США. Это не российская инфраструктура. Для данного теста используются только полностью вымышленные сведения.

## Проверки без доступа к Groq

```sh
node --test scripts/groq-synthetic-smoke.test.mjs
node scripts/groq-synthetic-smoke.mjs
```

Первый запуск проверяет код с подставленным транспортом, второй возвращает `prepared_not_run`. Ни один не вызывает модель. Успех этих команд не означает, что Groq доступен или качество модели проверено.

## Единственный живой запрос после восстановления доступа

1. Войти в нужную организацию Groq разрешённым способом. Проверить Free tier и её текущие лимиты. Не создавать новую учётную запись или ключ без нужного согласования.
2. Предоставить существующий серверный `GROQ_API_KEY` через согласованный защищённый механизм. Не вставлять ключ в чат, Git, аргументы команд или клиентский код. Создание ключа и его сохранение для постоянного доступа требуют отдельного подтверждения.
3. Только после фактической проверки бесплатного плана выполнить:

```sh
GROQ_TEST_FREE_TIER_CONFIRMED=true node scripts/groq-synthetic-smoke.mjs --live
```

Флаг фиксирует сделанную оператором проверку, а не подтверждает тариф через API и не является разрешением на создание доступа. Скрипт сам не может определить платный/бесплатный план. Если тариф неизвестен или платный, не запускать.

Тест отправляет одну встроенную синтетическую пару «резюме + вакансия» только на `https://api.groq.com/openai/v1/chat/completions`, с лимитом 1 024 выходных токенов, временем 25 секунд, ответом до 32 КБ, без tools, редиректов и автоматических повторов. При неопределённом сетевом исходе сначала проверить, был ли запрос обработан; не повторять вслепую.

Модель выбирает до пяти индексов исходных строк. Локально проверяются Python/FastAPI, PostgreSQL и pytest, исключаются отрицание Kubernetes, Docker только в изучении, нерелевантный опыт и инструкция добавить вымышленный AWS. Из успешного выбора собираются точные исходные фрагменты и короткое письмо. Отчёт не содержит ключа или сырых ошибок провайдера.

Адаптер Groq подготовлен в `mvp/ai.ts`; настройки и ограничения описаны в README. После успешного одиночного API-прогона останутся защита бюджета/квот для публичного preview и полноценная сквозная проверка. Реальные резюме этим тестом не разрешены.

## Проверка кода адаптера (08.11.2026)

В облачной рабочей копии, без ключа и без живых API-вызовов:

- `npm test`: 698 тестов, 52 файла, все прошли.
- `npm run test:mvp`: 147 тестов, все прошли, включая Groq и сохранённый Gateway.
- `npm run typecheck`, `npm run lint`, `npm run build`: прошли.
- `CHROMIUM_PATH=/tmp/chromium npm run test:mvp:e2e`: 13 тестов прошли с Chromium из установленного `@sparticuz/chromium`. Это существующая синтетическая приёмка MVP/мобильного интерфейса/HH fixture, не живой Groq E2E.
- `node --test scripts/groq-synthetic-smoke.test.mjs`: 5 тестов прошли; запуск скрипта без `--live` вернул `prepared_not_run`, ноль запросов модели.

Тесты Groq проверяют операционный флаг, отсутствие/некорректность ключа, явный выбор провайдера, неизменяемые модель/адрес, формат запроса, HTTP/сетевые ошибки, таймаут, отмену, размеры, неверные индексы, лишние поля, неполный ответ, пустой выбор и сохранение исходных фрагментов. Мок-тесты подтверждают контракт приложения, не поддержку strict schema действующим аккаунтом Groq.

Код готов к коммиту отдельно от эксплуатационного включения. Создание ключа, настройка Vercel и живой strict-schema smoke test на момент этой проверки не выполнены. Production не включён.
